# Dart standard

The rules for the Android app in `src/app/` (Dart and Flutter), why each exists, and what enforces it. [AGENTS.md](../../AGENTS.md#app-conventions) keeps the short form; [the app's README](../../src/app/README.md) explains how the app works.

Every rule marked with a tool runs in `make check-app`, which refuses any Flutter but the pinned 3.47.8 (with Dart 3.13.7).

## Layout

```text
src/app/lib/
  app.dart, main.dart   composition: the only place that builds platform ports
  state/<domain>/       controllers and their immutable states; imports no widgets
  screens/<domain>/     what the owner sees; reads controller state
  platform/             Android, BLE, NSD and Wi-Fi behind ports
  widgets/              widgets more than one domain uses
  theme/                the theme, and tokens generated from assets/brand/tokens.json
  src/rust/             generated by flutter_rust_bridge, never edited
src/app/test/           mirrors lib/
src/app/tools/wellfed_lints/   the analyzer plugin behind the architecture rules
```

## Rules

| Rule | Why | Enforced by |
| --- | --- | --- |
| **One state per controller.** A `ChangeNotifier` in `state/` exposes one immutable `state`. Exclusive modes are a sealed hierarchy, each carrying only its own data; concurrent concerns are fields of one immutable class, sealed where they carry data. Screens receive a function that makes their controller, so a test gives them fakes. | A field that can't apply in a mode can't be read in it, and a `switch` must handle every mode. | `single_state`; the compiler for `switch` |
| **No state package.** No Riverpod, Bloc or dependency injection package. | `ChangeNotifier` is enough, and a package's retries must not touch a feed. | Review |
| **Layers point one way.** `state/` never imports `screens/` or `widgets/`. | Controllers stay testable without a widget tree. | `state_imports_no_ui` |
| **Screens go through controllers.** Screens may name generated Rust types, but reach Rust calls and `platform/` only through a controller. | One place holds each rule about what the feeder is asked. | `ui_no_platform`, `ui_no_bridge_calls` |
| **No widget helpers.** A method or function does not return a `Widget`. Write a widget class, or a `Builder` at the one place it is used. | A class gets its own element, rebuild boundary and `const`. | `no_widget_helper` |
| **500 lines.** A hand-written file stays within 500 lines, tests included. Generated files are exempt, with no other exceptions today. A class too long for that splits into `part` files of extensions, as `InstallFlow` does. | A long file is doing two jobs. | `file_length` |
| **Strict lints, no warnings.** An explicit list from Flutter's own, plus `discarded_futures`, `use_build_context_synchronously`, `unnecessary_ignore` and `document_ignores`, minus `always_put_control_body_on_new_line`, which `dart format` undoes. Infos are errors. | A warning nobody fixes hides the next one. | `dart analyze --fatal-infos` |
| **Deliberate exceptions.** An `// ignore:` covers one line and gives its reason on that line. | The next reader knows whether it still applies. | `document_ignores`, `unnecessary_ignore` |
| **One format.** `dart format` at 120 columns, and package imports only. The generated bindings keep the generator's format. | No formatting in review. | `dart format --set-exit-if-changed`, `always_use_package_imports` |
| **Generated contracts.** Rust types arrive through flutter_rust_bridge, tokens through `tokens.g.dart`, and the feeder's limits and role matrix through `limits.g.dart` and `roles.g.dart`; never hand-write a copy. Commit regenerated files with the change that caused them. | Two copies drift. | `check-app` fails on a stale regeneration |
| **Native data.** Sealed classes, records and primary constructors. Use `freezed` only where `copyWith` or equality earn it. Public collections are unmodifiable. | Less generated code, and no caller can change a state in place. | Review |
| **Errors become state.** Only `state/` and `platform/` catch: `state/` turns a bridge or platform error into typed state, and `platform/` catches only a missing plugin. Every catch names its type; one that must turn any failure of a run into a screen says `on Object`. | A screen draws what happened and can't lose a failure, and a run can't hang on an error nobody catches. | `catch_in_controllers`, `avoid_catches_without_on_clauses` |
| **No `!`.** Narrow with a check or a pattern; an exception is an `// ignore:` stating the invariant. | An assertion moves a wrong assumption to where it crashes. | `no_bang` |
| **Timers have a reason.** `Timer` and `Future.delayed` live only in `state/` or `platform/`, with a named constant giving the hardware or protocol reason; prefer an event. A screen that counts down uses `state/clock/`. Widget tests pump time and never wait for real. | A guessed wait hides a race. | `timers_in_state_or_platform` |
| **Docs where others call.** `public_member_api_docs` applies in `state/` and `platform/`; elsewhere, comments only say why. | Those two layers are what the rest of the app calls. | Nested `analysis_options.yaml` in those folders |
| **Feeding safety.** Every feed goes through the device API, the app holds no schedule logic, and a retry never resends a request the core marked uncertain. | A retried feed can dispense twice. | Review; `test/` covers each outcome |
| **Accessible.** WCAG 2.2 AA. Text is literal English until a second language is planned. | People use the app with a screen reader too. | Accessibility tests; review for the rest |

## Tests

| Layer | Covers | Where |
| --- | --- | --- |
| Widget and state | Each screen and controller, with fake ports and no Rust | `test/<domain>/` |
| Accessibility | Android's 48dp targets, labels and contrast on every screen, in both themes | `test/accessibility/` |
| Goldens | The shared widgets and the key screens, in both themes | `test/golden/` |
| Smoke | The real bridge against `wellfed-feeder-sim`: a session, settings, the schedule, a feed and a join | `test/smoke/` |
| The plugin | Each rule of `wellfed_lints`, firing and not firing | `tools/wellfed_lints/test/` |

Goldens belong to Linux, since font rasterizers differ by as much as a real change: a dropped letter moved 22 pixels, and macOS's fonts move thousands. x86_64 and arm64 Linux agree within the comparator's tolerance, where no pixel may have a channel move by more than 8 of 255. So a deliberate colour change that small passes, and a token change needs its images looked at. On any other host `make app-goldens` (and so `make check-app`) runs them in a Linux container (Docker, or `CONTAINER=podman`). After a deliberate change, run `make app-goldens UPDATE=1` and look at the images: a golden proves nothing changed, not that it looks right.

The smoke tests run when `WELLFED_SMOKE_TARGET` names the directory holding the bridge and the simulator, as `make check-app` does, and start and stop the simulator on a loopback port themselves. No host test has a radio to reach, so BLE setup, the install and the restore have no smoke test; the desktops' link is tested over fake bridge handles (`test/platform/desktop_bluetooth_test.dart`).

## Before a release

The host checks do not prove the app works on a phone. Run these by hand on a real phone and feeder:

1. Set up a new feeder over Bluetooth, from setup mode to the Home card. Start with the phone's Bluetooth off: the app should say so, offer **Turn on Bluetooth**, and go on to the search once it is on.
2. Recover a feeder over the LAN with its window open.
3. Feed one portion. Check the bowl against what the app says.
4. Add a meal, edit it, and delete it.
5. Invite a second phone, join with its camera, and remove it.
6. Install Wellfed over stock, then restore stock from the backup.
7. Update the firmware with the app in the background and the screen off.
8. Turn on TalkBack and go through Home, a feed and the schedule.
9. Alerts at home, on a locked phone on the feeder's Wi-Fi: force each alert you can (a jam, an empty hopper, no clock, a client joined), and check each notifies once and comes off when the feeder clears it. Note the delay and the battery overnight with "instant while home" off and on.
10. Start a Bluetooth setup, then make the periodic catch-up run and turn "instant while home" on and off. The setup should go on to the Home card. To run the catch-up, find its job id with `adb shell dumpsys jobscheduler | grep -A3 io.github.isaacduarte.wellfed` (the `JOB #u0a…/<id>` line naming `androidx.work.impl.background.systemjob.SystemJobService`), then run `adb shell cmd jobscheduler run -f io.github.isaacduarte.wellfed <id>`.
11. Unplug a feeder with the phone at home: "Can't reach" should come after about 10 minutes with instant mode on, and never while the phone is away from home.
12. On each desktop (macOS, Linux on GNOME and on a desktop with no notification server, Windows), with the app open on the feeder's network: force an alert and check one notification appears in the same words as on the phone, then comes off when the feeder clears it. Click it with the window minimized or behind another: the window should come forward on that feeder's alerts. On a Mac, check the app asks to post when it first has a feeder; with no notification server, check the alert settings say so.

The integration suite no longer makes the trip through stock, so make it on the bench with the same build. It needs the owner at the panel, and no host test stands in for it:

1. **Back to stock.** With TCP 1883 and 8088 from the hotspot admitted ([the bench host's firewall](stock-server.md#the-bench-hosts-firewall)), run the `restore-stock` job ([bench](../devices/plaf103/bench.md#stock-and-back)). The job runs no broker, so to watch stock report, run `wellfed-stock serve --device plaf103 --config private/installer.json` and then `wellfed-stock status --device plaf103 --config private/installer.json`. You should see it online with `softwareVersion` 1.1.15; `status` stops with an error until stock enrolls. A finished install removes `private/installer.json`, so if it is gone, write it again with `wellfed-stock init-installer --device plaf103 --mqtt-listen 10.42.103.1:1883 --output private/installer.json` and add `--enroll-minutes 15` to `serve`. Stock reports here only if its last setup frame named this host, which after an install from a phone or a vendor setup it did not: read its `app_main:version:` banner on the UART instead. Stop `serve` before the next step.
2. **Forward to Wellfed.** Run the install in the app, from a real Reset hold ([running it](../firmware/install-bench-checks.md#running-an-install-on-the-bench)). The frame erases stock's plans, so the run sets stock's clock. You should see the build confirmed on bank 1, and the backup offered for saving.
